# 02 – UX, UI und Designsystem

## Reihenfolge

```text
Nutzeraufgaben
→ Informationsarchitektur
→ User Flow
→ Wireframes
→ kurzer Usability-Test
→ Designsystem
→ High-Fidelity-Design
→ Accessibility- und Technikprüfung
```

## Ein Screen, eine Hauptaufgabe

Für jeden Screen dokumentieren:

- Nutzerziel
- primäre Aktion
- sekundäre Aktionen
- benötigte Daten
- Ladezustand
- Leerzustand
- Fehlerzustand
- Offlinezustand
- Erfolgzustand
- Berechtigungen
- Accessibility-Anforderungen
- Testkriterium

## Designsystem vor Massenausbau

Definiere:

- Farbrollen statt zufälliger Farben
- Typografie-Skala
- Abstandsraster
- Radien, Schatten und Flächen
- Komponenten und Varianten
- Icons und Bildsprache
- Breakpoints
- Dark Mode
- Motion- und Reduced-Motion-Regeln
- Formulare, Validierung und Fehlermeldungen

## Referenzen richtig verwenden

Mobbin, Dribbble, Behance oder fremde Apps sind Referenzen, keine automatisch übertragbare Vorlage.

1. vollständige Flows sammeln;
2. UX-Muster erkennen;
3. eigene Informationshierarchie festlegen;
4. Rechte und Originalität beachten;
5. eigenes Designsystem erstellen;
6. nur einen Kernscreen umsetzen;
7. gerendertes Ergebnis mit Referenz und Tokens vergleichen;
8. erst danach weitere Screens bauen.

## Accessibility-Baseline

- sinnvolle Screenreader-Namen
- logische Fokusreihenfolge
- Textvergrößerung
- ausreichender Kontrast
- ausreichend große Touch-Ziele
- Alternative zu reinen Gesten
- Reduced Motion
- keine Information nur durch Farbe
- verständliche und konkrete Fehlermeldungen

## Design Review

Bewerte getrennt:

1. Struktur
2. Inhalt
3. visuelle Hierarchie
4. Konsistenz
5. Zustände
6. Accessibility
7. technische Umsetzbarkeit

## Häufige Fehler

- Design vor User Flow
- fremdes Design 1:1 kopieren
- zu viele Karten und Navigationsebenen
- fehlende Lade-, Leer- und Fehlerzustände
- Komponenten pro Screen neu erfinden
- Desktop- und Mobile-Verhalten nicht gemeinsam planen
- nur statische Screens testen
